# Module 2 — Data Contract Notes

## Application-level validation (Pydantic)

- Machine, technician, and job identifiers must be positive.
- Machine and technician names must be non-empty; machine names have a minimum length of one.
- Serial numbers must have at least three characters and start with `SN-`.
- Installation and job dates are parsed as Python dates.
- `part_nos` is a list; persisted job/part links use one `job_part` row per pair.

## Database-level rules (SQLAlchemy metadata and generated DDL)

- Primary keys identify rows. Machine name and serial number are unique.
- `maint_job` references machine and technician; `job_part` references jobs and parts and uses a composite primary key.
- Required fields are `NOT NULL`; IDs and part prices have checks; the serial prefix is checked.
- Unit price is declared `NUMERIC(9,2)`.

`contract-ddl.sql` is generated by `python Module02/contract.py`. SQLite foreign-key enforcement is connection-specific, so each connection must execute `PRAGMA foreign_keys=ON`. SQLite's `DATE` and `NUMERIC` declarations do not by themselves guarantee valid calendar dates or fixed-scale decimal arithmetic. Pydantic validates application inputs; the DDL enforces keys, nullability, declared checks, and relationships when foreign keys are enabled.

## Conclusion

Application and database validation cover different entry points. Keep both sets of rules aligned when the contract changes.
