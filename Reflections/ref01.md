# Module01 Reflection

## My Take-away

Module01 gave me my first practical experience with databases and the workflow used in this course. I learned that the portfolio is not only about getting the correct answer, but also about showing my work, testing it, and keeping evidence of what I did.

One important thing I want to remember is **“verify before you trust.”** This was especially important when using LLM-generated SQL. Instead of assuming that an AI answer is correct, I learned to run the query and check the actual result.

I also learned that SQLite is an embedded database, so it can run directly inside a local application without needing a separate database server. This makes it useful for many local applications.

My advice for future modules is to work step by step, keep my files organized, and test each command before moving to the next task.

## What Was Good?

The most useful part of Module01 was setting up the complete database toolchain and actually working with real data instead of only learning database concepts from slides.

Creating my GitHub portfolio was also useful because I learned how to organize my work and use Git for version control. I also learned why `.gitignore` is important, especially for keeping database files and other files that should not be uploaded to GitHub.

Another good part was creating and loading the telemetry data into SQLite. I could then query the data and see real results. Using Datasette was also interesting because it gave me another way to explore and view the database.

## What Was Difficult?

The most difficult part for me was setting up and using the tools correctly, especially working with the terminal and SQLite commands.

At some points, I had problems entering commands or opening the database file. I also had to understand how different commands worked in PowerShell and how they were different from commands shown for other operating systems.

Another difficult part was understanding the database workflow at the beginning. I had to learn how the Python files, CSV data, SQLite database, GitHub repository, and Datasette were connected.

These problems were difficult at first, but solving them helped me become more comfortable with the tools.

## Struggling and Exploration

One interesting part of the struggle was getting the telemetry data into SQLite and then checking it using Datasette. At first, the process was not completely clear to me, but after testing the commands and fixing the problems, I could see the data in the database.

I also explored the database using SQL queries and checked the results instead of only assuming that the commands worked. This made the process more interesting because I could see how the data changed from a CSV file into a database that I could query.

There were some problems where I needed to find out why a command was not working. These were useful learning experiences because I learned that an error does not always mean that the whole project is wrong. Sometimes I only needed to check the command, file path, or database location.

## Interaction with Peers and Instructors

Working with my group was helpful during Module01. When I was stuck, I could discuss the problem with my group members and compare our approaches. This helped me understand some tasks more easily and gave me confidence to continue when I had problems.

My friend Sebastian helped me clone the template from the professor's GitHub repository at the beginning of the project. This was especially helpful because I was still learning how GitHub and repositories worked.

Other members of the group also helped by discussing problems, sharing ideas, and explaining things when someone was unsure about a task. I found this group interaction valuable because sometimes a problem became easier to understand after discussing it with other students.

## Help and Extra Work

I received help from members of my group during Module01. Sebastian helped me with cloning the course template from the professor's GitHub repository, and other group members helped through discussions and sharing ideas when I had difficulties.

This support was valuable because it helped me solve problems faster while also learning how to do the tasks myself.

I also spent extra time troubleshooting the terminal, SQLite, Python, and Datasette when commands did not work as expected. I created and tested the telemetry database, wrote SQL queries, used Python to work with the database, and documented my results in the portfolio.

I learned that getting help from the group does not mean that someone else does the work for me. It can help me understand the problem and find the right direction, while I still need to test and verify my own work.

## Overall Reflection

Module01 was a good introduction to the way this course works. I learned not only about databases but also about working independently, documenting my process, working with my group, and verifying my results.

The biggest lesson for me is that getting an answer is not enough; I need to verify that the answer and the process are correct.

I also learned that problems with tools and commands are part of the learning process. When something does not work, I should check the error, investigate the cause, and try again instead of giving up.

Module01 gave me a good foundation for the later database modules, and I feel more confident working with SQLite, Python, GitHub, and database tools than I did at the beginning.
